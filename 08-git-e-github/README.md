# 08. Git e GitHub

O histórico do repositório é documentação: conta **o que** mudou, **por que** e
**quem revisou**. Estas práticas tornam esse histórico legível por pessoas e por
ferramentas (changelog, versionamento e releases automáticos).

| Tópico | Resumo |
|---|---|
| [Conventional Commits](conventional-commits/) | Mensagens de commit estruturadas e legíveis por máquina |
| [Pull Requests](pull-requests/) | PRs pequenos, descritos e verificados antes do merge |
| [SemVer e changelog](semver-e-changelog/) | Versões que comunicam compatibilidade e um registro humano das mudanças |
| [Code review](code-review/) | O que revisar, em que ordem e com que tom |

Este próprio repositório segue tudo isso: cada seção chegou por um PR com issue
vinculada, CI verde e merge por *squash* em uma `main` protegida por ruleset.
